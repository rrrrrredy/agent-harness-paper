# Claim Traceability Matrix

This matrix maps manuscript claims to committed evidence and explicit claim boundaries. It is a review aid, not a new evidence source.

| Claim area | Manuscript claim | Primary evidence | Validation or audit hook | Boundary |
| --- | --- | --- | --- | --- |
| Harness scope | An agent harness should be treated as runtime, evaluation, observability, permissions, replay, audit, and review rather than only final-answer evaluation. | `paper/main.tex`, `docs/claim_boundaries.md`, `evidence/inventory.md` | `scripts/check_public_traces.py`, `scripts/check_tex_sources.py` | Design framework claim; not a deployed-production proof. |
| Thin harness, strong contracts | Capability-patch harnesses can become technical debt, while system-boundary harnesses encode more durable trust boundaries. | `paper/main.tex`, `evidence/inventory.md`, `evidence/source_audit.md` | `docs/claim_boundaries.md`, `scripts/check_public_traces.py` | Conceptual synthesis from first-party artifacts and related work. |
| First-party artifact base | Skill, memory, security, scheduler, self-audit, and AI-radar artifacts show recurring boundary concerns. | `evidence/github_snapshots.md`, `evidence/source_audit.md`, `evidence/inventory.md` | `scripts/audit_source_evidence.py --offline` | Repository metadata and source signals support bounded interpretation, not full runtime behavior. |
| Upstream PR examples | OpenClaw and Hermes PRs are examples of dry-run, scheduler semantics, reusable sessions, and scoped recall boundaries. | `evidence/github_snapshots.md`, `evidence/github_evidence.json`, `evidence/inventory.md` | `scripts/check_public_traces.py` | PR metadata and summaries support boundary examples, not broad claims about upstream systems. |
| Pilot benchmark shape | The 24-case benchmark evaluates trigger routing, stateful tool use, permission/security, memory scoping, and replay/recovery. | `benchmark/cases.jsonl`, `harness/core.py`, `docs/data_dictionary.md` | `pytest`, `scripts/check_run_manifest_alignment.py` | Pilot harness shape; not representative of all agent tasks. |
| Pilot results | Reported metrics come only from committed raw JSONL and regenerated tables. | `experiments/raw/*.jsonl`, `results/tables/*.md`, `results/tables/*.tex`, `figures/success_by_variant.svg` | `scripts/run_checks.py --mode regenerate`, `scripts/run_checks.py --mode validate` | No general model/provider superiority claim. |
| Live provider status | DeepSeek rows are live API outputs; Kimi row is an authentication/provider availability result, not model behavior. | `experiments/run_manifest.md`, `experiments/raw/deepseek_live.jsonl`, `experiments/raw/kimi_live.jsonl` | `scripts/check_run_manifest_alignment.py` | Bounded to committed raw files, endpoint, model id, and recorded run state. |
| Rerun safety | Future live reruns should use credential preflight, ignored smoke outputs, and promotion review before raw-result replacement. | `scripts/check_provider_credentials.py`, `scripts/run_model_experiment.py`, `docs/live_rerun_promotion.md` | `pytest`, `scripts/build_artifact_archive.py --check` | Requires valid credentials in process environment; credentials are never committed or printed. |
| Artifact package readiness | The repository can validate, regenerate, build a checked PDF artifact, and build a source archive excluding local residue. | `artifact_manifest.json`, `docs/artifact_release_index.md`, `docs/submission_readiness.md`, `.github/workflows/validate.yml`, `.github/workflows/latex.yml` | `scripts/run_checks.py --mode validate`, `scripts/build_artifact_archive.py --check`, GitHub Actions | Venue template, license, anonymization, and live rerun decisions remain external. |
